# SDK ecosystem maturity audit, 2026-10-07

Requested direction: SDK improvements first; Windows PC / GDK only / D3D12;
007 titles are the representative validation set. Project Helix is a future
deployment validation target, not a supported-device claim. This review covers
the six related repositories, not unrelated personal projects such as SaveBridge
or the portfolio. It inventories owned sources and reviews build/export,
ownership/lifetime, guest ABI, issue readiness and human/agent handoff hotspots.
It is not a claim of exhaustive line-by-line verification or a security audit.

## Existing strengths to preserve

C++23, pinned formatting, typed guest exports, explicit endian/packing rules,
source provenance, ADRs, a synthetic GPU readback harness, PPC hardware corpus,
installed-consumer tests and a runtime/plugin handshake already exist. Guide
dependencies are pinned and its standalone CI builds Debug/Release without
the SDK. Title repositories allowlist redistributable configs/docs and keep
generated code/assets private. Keep those boundaries.

The memory destructor already clears its active singleton; the combined unit
abort is not evidence of a missing destructor cleanup. A shared live test
fixture and independent memory instances can conflict in one process. The
supported isolated CTest contract and its limits must remain explicit.
Raw-pointer counts alone do not establish ownership bugs: mapped guest memory,
handle tables, intrusive refs and borrowed views need contract-specific review.

## Standards and review contract

[Development guidance](development.md) turns the review into a common entry
point for people and agents: module map, C++23/RAII and guest ABI exceptions,
target-based CMake, lock/callback lifetimes, source pins and measurable gates.
Sources: [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines),
[CMake build-system guidance](https://cmake.org/cmake/help/latest/manual/cmake-buildsystem.7.html),
[Clang tooling](https://clang.llvm.org/extra/clang-tidy/),
[Microsoft's GDK](https://github.com/microsoft/GDK), and
[Xbox's Helix statement](https://news.xbox.com/en-us/2026/03/11/project-helix-building-next-generation-of-xbox/).
These are engineering guidance and verified platform scope, not a certification
or a claim that every rule/check passes across all legacy code.

See [the Edge GPU comparison](edge-gpu-review-20261007.md) for exact source
classification and adoption boundaries. Actual checks and known limitations
belong in [release evidence](release-evidence.md).
